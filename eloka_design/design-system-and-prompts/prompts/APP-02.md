Page 2 of the applicant flow, the same for both paths (DigiLocker and step by step): the partner who is applying enters their own mobile number, then a one-time code. This is the only place the mobile number is collected; later steps reuse it.

**PLATFORM:** Web, Mobile-first

**FRAME A — Mobile number:**
1. Top bar: back arrow, "ELOKA" wordmark, "Help" on the right.
2. A small chip showing the chosen path: "Applying with DigiLocker" with a "Change" link.
3. Title "Your mobile number". Line: "We'll use this number to sign you in and to contact you about this application."
4. Field "Mobile number" with a fixed "+91" prefix. Helper: "We'll send a 6-digit code by SMS." Error variant: "Enter a valid 10-digit mobile number".
5. Full-width primary button "Send code".

**FRAME B — Code:**
1. Title "Enter the code". Line "Sent to +91 XXXXXX3210" with a "Change" link.
2. Six digit boxes. "Resend code in 0:28".
3. Full-width "Verify" button.
4. Error variants: "Incorrect code — 2 attempts left", "Code expired — resend a new one".
5. Info variant: "This mobile already has an active ELOKA account" with "Contact support".

No marketing content, no statistics, no time estimates.
