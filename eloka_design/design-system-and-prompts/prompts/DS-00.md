A component reference sheet for the ELOKA platform design system: one long desktop page that lays out every reusable UI building block in clearly labelled sections, so designers and developers can check each component and state side by side.

**PLATFORM:** Web, Desktop-first (show mobile sizes where noted)

**PAGE STRUCTURE:**
1. **Header:** Page title "ELOKA components" with a one-line subtitle "Reference sheet — platform screens". No navigation.
2. **Buttons section:** A grid with one row per variant — Primary, Secondary (outlined), Ghost, Danger, Link. Columns show Default, Hover, Focus (visible focus ring), Disabled and Loading (inline spinner replacing the label, same width). A second row shows sizes Small 32px, Medium 40px and a full-width Large 48px mobile button.
3. **Form fields section:** Text input in five states — empty with label above and helper text below; filled; focused; error (error message below with a small icon, replacing the helper text); disabled. Also a select dropdown, a textarea with a character counter "0 / 1000", a checkbox and a radio group with three options, and a required-field marker plus an "(optional)" label example.
4. **OTP section:** Six separate square digit boxes with a "Resend code in 0:28" line beneath, plus the same row in an error state ("Incorrect code — 2 attempts left").
5. **Status pills section:** Pill-shaped chips, each with a small dot and sentence-case text, grouped by tone — Neutral: "Not started", "Skipped"; Info: "In progress", "Submitted", "Under review", "Checking"; Warning: "Correction required", "On hold", "Needs review"; Success: "Completed", "Verified", "Approved", "Signed"; Danger: "Failed", "Rejected", "Expired", "Withdrawn"; Locked: "Locked" with a small lock icon.
6. **Cards section:** A section card with a header row (title on the left, a status pill and a text button on the right), a body with a two-column label/value list (labels like "Business name", "Entity type", "PAN" shown masked as XXXXX1234X), and a footer row with Secondary and Primary buttons.
7. **Document tile section:** Three stacked document rows — "Address proof" (file icon, file name "address-proof.pdf", "1.2 MB", pill "Waiting for review", actions View / Replace / Remove); "Incorporation certificate" (pill "Verified"); "Bank proof" (pill "Rejected" with a highlighted reviewer note strip "Image is blurred, please upload a clearer copy").
8. **Progress section:** A vertical step rail of 13 steps (Mobile, Consent, Program, Business PAN, Business details, Email, Signatory KYC, Live photo, Documents, Bank account, White-label setup, Declaration, Agreement) where the first three are completed (check icon), the fourth is current (highlighted), and the rest are not started; beside it the compact mobile version "Step 4 of 13" with a thin progress bar.
9. **Table section:** A review queue table with columns Application, Company, Entity type, Status (pill), Submitted, Assigned to, Flags; four fictional rows (e.g. "onb_7Q2K", "Sample Traders Pvt Ltd", "Private Limited", "Submitted", "21 Oct 2026", "Unassigned", "1"); a filter bar above (status select, "Assigned to me" toggle, search input) and a "Load more" secondary button below.
10. **Feedback section:** A confirmation dialog "Reject application" with a required reason select, a "Message to applicant" textarea, a separate "Internal note" textarea, and Cancel plus a Danger "Reject" button; an empty state ("No applications match these filters" with a short hint and a "Clear filters" button); an error state ("Something went wrong" with a "Try again" button and a small "Details" link); a pending check card ("We're checking with the provider" with a small progress indicator and "Check again" link); a skeleton loader shaped like a card with three text lines; and a dark toast "Saved".
11. **Timeline section:** A vertical timeline with four events, each showing a time like "21 Oct, 10:42", an event title ("Application submitted", "Reviewer assigned", "Correction requested", "Resubmitted") and a status pill.
12. **Masked value section:** Chips showing "XXXXX1234X", "XXXXXX4321" and "XXXXXX3210" with a small labelled copy icon button and a "Reveal" text button.

Interactions to indicate: visible focus rings on every interactive element, hover states on buttons and table rows, and minimum 44px touch targets for mobile sizes. All data is clearly fictional sample data.
